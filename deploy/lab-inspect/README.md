# 内部检视工具：怎么开、怎么看

三样东西都在实验室电脑的 Docker 里跑，只读，只有那台电脑自己连得到。从 Mac 看要先开隧道。

## 平常怎么看（在 Mac 上）

1. 开隧道（开着的时候才看得到，Ctrl+C 结束）：

   ```bash
   scripts/inspect-tunnel.sh
   ```

2. 打开网页：

   顶栏有四个入口（11-17 起，设计稿 `docs/superpowers/specs/2026-11-17-panels-structure-design.md` 第二节），右边「工具」小选单里是资料库和爬虫进度：

   | 要看什么 | 入口 | 网址 |
   |---|---|---|
   | **每晚从爬取到换库跑得正不正常、各步花多久、要你处理什么（先看这个）** | 每晚運行 | http://127.0.0.1:18878 |
   | 全部 111 个网站收了多少、缺什么（资料总览，deploy/lab-overview）；点网站名或右边的「這個網站的詳情」进单站页 | 網站 | http://127.0.0.1:18879 |
   | 一个网站的全部：每一步进多少出多少、上次换库它变了什么、网页核查、各类型文件和没日期的原因 | 網站 → 单站页 | http://127.0.0.1:18878/site?site=c.nknu.edu.tw/aca |
   | 学生的 AI 搜索时收到什么；第二个分页「為什麼這樣排」是原来的搜寻测试；什么都没问时下面是 33 题成绩 | 搜尋 | http://127.0.0.1:18878/try |
   | 找一份文件或一个网页（标题的字、网址、文件编号，简体繁体都认）；什么都没打时是全校的网页核查 | 找文件 | http://127.0.0.1:18878/doc |
   | 资料库（Datasette） | 工具 | http://127.0.0.1:18001 |
   | 爬虫自己的看板 | 工具 | http://127.0.0.1:18877 |

   旧网址照样能开，会转到新的地方：`/search` → 搜尋的第二个分页，`/trace`（没给文件）和 `/check`（没给网页）→ 找文件，`/pipeline/site`、`/check?site=` → 单站页。一份文件的追踪 `/trace?ref=…`、一页的核查 `/check?url=…` 没有搬。

3. 亲手调 `search`、`read`（MCP Inspector）：另开一个终端机跑下面这条，它会自己打开一页。

   ```bash
   npx @modelcontextprotocol/inspector --server-url http://127.0.0.1:18766/mcp --transport http
   ```

4. 两条命令（另开一个终端机，先告诉它检视台在哪）：

   ```bash
   export NKNU_OPS_URL=http://127.0.0.1:18878
   ```

   ```bash
   uv run --no-sync nknu search "115-1 停修" --explain
   ```

   ```bash
   uv run --no-sync nknu trace <网址或文件编号>
   ```

   想知道某一份为什么没排上来，加 `--doc <文件编号或网址>`。要给程序读就加 `--json`。

## 在实验室电脑上（PowerShell）

compose 档放在 `C:\nknu-transfer\inspect\compose.yaml`。

| 要做什么 | 命令 |
|---|---|
| 三个都开 | `docker compose -f C:\nknu-transfer\inspect\compose.yaml up -d` |
| 看有没有在跑 | `docker compose -f C:\nknu-transfer\inspect\compose.yaml ps` |
| 换程序以后 | `docker compose -f C:\nknu-transfer\inspect\compose.yaml restart` |
| 换库以后 | `docker compose -f C:\nknu-transfer\inspect\compose.yaml restart datasette` |
| 看检视台的纪录 | `docker compose -f C:\nknu-transfer\inspect\compose.yaml logs --tail 50 ops` |
| 全关 | `docker compose -f C:\nknu-transfer\inspect\compose.yaml down` |

要注意的四件事：

- **换库以后只重启 Datasette。** 建库程序把 `aca.db` 换掉以后，Datasette 还开着旧的那个档，要重启才会换。检视台和 MCP 服务每次都重新开库，马上就是新的（向量索引看库的建库时间，自己重载），不要一起重启：重启检视台会触发约 17 分钟的整轮网页核查，和爬虫抢 D 槽的机械硬盘。爬虫从 11-17 起每天 01:00 自动跑每晚更新（工作排程器「nknu-nightly-update」，平常约一小时），**01:00～04:00 不重启检视台**（导出那一批上线后时段会更长，爬虫会再说）。内容 session 打算在每晚进库的脚本里换库后自动跑这一句（2026-11-16 设计稿，等用户点头）。检视台每一页上面写着它读的库是什么时候建的。
- **检视工具用的是自己那份程序**，装在磁碟区的 `/work/inspect-code`，不是建库用的 `/work/src`。所以平常送 `code.tar` 不会换到它；建库的程序更新以后，要照下面「换程序」重装一次，检视台看到的打分和「没进库的原因」才是新的。忘了也会知道：检视台每一页上面写着它是什么时候装的，建库的程序和它装的那份不一样时，页面最上面会出一条红色的提醒。
- **电脑重开机以后**要有人登入、Docker Desktop 开着，三个服务才会自己起来（和爬虫看板一样）。
- **检视台的「测试题成绩板」是现算的。** 首页和搜索测试那一页最上面，每道测试题一格，写它最好的一份标准答案排第几。库换过、或隔了一天以后第一次打开那一页，它会在背景把 33 题各搜一次（一次一题，约一分钟，用显卡），格子一题一题填上；算过就记着，不再重搜。你自己搜的问题会排在它两题之间，最多等一题。

## 搜尋（检视台「搜尋」）

http://127.0.0.1:18878/try 像学生的 AI 一样搜索：最上面是一个大搜索框和一个「搜尋」钮，下面一排是搜索工具的其他参数（选项是一排按钮、预设那个已按下，滑过看说明；数字是小框，带上下限；说明里提到单位的参数会从服务的开场说明里列出可选的单位，也可以自己打）。这些全照服务的工具清单生成，页面里没写死工具名或参数（接口那边改了，这一页自己跟上）。读一份的工具不另放表单：每一笔结果下面有「讀這一份」，说明里写到的读法（如「目錄」）也是一个钮；目录里的每一节点了就读那一节。送出后左边是 agent 收到的原文、右边是排版好的结果，每一笔还可以看「為什麼排在這裡」（原来的搜寻测试，第二个分页）。agent 开工前读到的开场说明和工具清单收在下面「agent 先看到的」（左边原样、右边排版，写着字数和大约多少 token）；工具清单里还有别的只读工具时，放在「其他工具」里。检视台从容器里连 `http://mcp:8766/mcp`（compose 的 `--mcp-url`），浏览器不直接连 MCP；只调用工具清单标成只读的工具，一次只查一个，别人在查时会说「正在查」而不是排队；服务刚重启后第一次查要载入模型，约 30 秒。

## 网页核查（检视台第三页）

不用记网址：打开 http://127.0.0.1:18878/check，结论一行下面先是全校合起来的「沒抓到的」「要查的」（正文区、附件区里的，同一个网址只算一条，影响最多页的 8 条在前，写出在哪个网站、为什么、几页），再下面是网站清单，每个网站一行，写着抓下来几页、正文区有漏几页、选单没抓到几个链接、要查几页、这一页本身没抓下来几页，正文区有漏的网站排最前面；点表头照那一栏排，再点一下回来。上面那个框打几个字（网站名、简称、网页的名字、网址的一段都行，简体繁体都认）就在下面列出符合的网站（排前面）和网页；贴网址或文件编号照旧直接核查那一页。点一个网站，看到它所有页合起来「沒抓到的」「要查的」（同一个链接只列一次，写出现在几页；点一条从右边滑出详情栏：它是什么、账本怎么说、出现在哪几页，下面是存档里那一页、它的位置框出来，不换页也不开学校网页；要看学校现在的样子，按栏里的「開學校網頁 ↗」），下面是它的网页清单，有漏的排前面，上面四个小按钮（正文區有漏、只漏選單、要查、這一頁沒抓下來；学校已删除的页照样列在清单里，不算没抓下来）按一下只看那种、再按一下回到全部。核查一页时最上面一行是「网站名 › 这一页」，还有「下一個有漏的頁 →」。

这些清单是检视台在背景把账本里抓下来的网页一页一页核查出来的（和打开一页时用的是同一套规则）：检视台重启以后第一次打开网页核查时开始，在检视台里用一条线程，四万八千页约 17 分钟（11-16 在实验室量：读过的存档一页约 0.02 秒，第一次读的慢很多，因为 WARC 在 D 槽的机械硬盘上）；打开哪个网站就先核查那个网站，页面上写进度，还没核查到的写「核查中」。结果只放在记忆体里（磁碟区都是只读的），检视台重启就重算；账本变了（爬虫写过）也重算，新结果出来以前旧的照旧显示、写明是旧的。compose 档不用改。

贴一个网址（或文件编号），左边是存档里的这一页（学校的 CSS、JavaScript 不跑，所以是素的），会进库的正文区有虚线框、选单等不进库的盖一层灰；每个链接、图片、按钮按账本的状态上色（绿＝抓到了，绿加橙点＝內容可疑，灰＝照规则不抓，橙＝下一轮，橙色虚线＝還沒決定，红＝失败，红色虚线＝账本里根本没有）。右边最上面一行是结论（这一页漏了没有、漏在哪、谁来补），下面分「沒抓到的」「要查的」两张清单，正文区的排前面；点一条左边会闪一下它的位置。

- 点「開真實網頁」，学校现在的这一页开在萤幕右半边的另一个视窗；之后在左边点链接，两边一起跳。浏览器只在「点一下」的时候准开视窗，所以直接贴网址打开 `/check?url=…` 时要先点一次这个按钮。
- 只读：检视台只读挂载爬虫的磁碟区 `nknu-crawl`（账本）和 `D:\nknu-crawl\warc`（WARC），不连学校的服务器。账本的 `-wal`、`-shm` 不在、又因为唯读打不开时，才改用 `immutable=1` 读（页面「要注意」会写「帳本用唯讀快照讀」）：爬虫没在跑时这样读是对的；`-wal` 里还有纪录、或是别的错误（忙、锁住）时不这样读，页面说「帳本正在寫入」，过一下再试（只读挂载下没在爬的时候测过，爬的时候没测过）。
- 设计：`docs/superpowers/specs/2026-11-16-page-check-design.md`（不用记网址的入口是第六节）；程序：`src/nknu/ops/pagecheck.py`（一页的资料）、`check_page.py`（一页的页面）、`sweep.py`（背景逐页核查、网站和网页清单的资料）、`check_sites.py`（入口和网站页）。

## 换程序

为什么不用平常的 `code.tar`：它带的是整个工作区，别的 session 改到一半的档也会一起过去。检视工具只送自己的档。

1. 在 Mac 上打包（写到仓库外面）：

   ```bash
   deploy/lab-inspect/pack.sh
   ```

2. 照它印出来的那一行送到实验室电脑的 `C:\nknu-transfer\inspect\`（只经 SSH）。

3. 在实验室电脑上装，再重启：

   ```
   docker run --rm --network none -v nknu-work:/work -v C:\nknu-transfer\inspect:/in:ro nknu-pipeline bash /in/install.sh
   docker compose -f C:\nknu-transfer\inspect\compose.yaml up -d
   docker compose -f C:\nknu-transfer\inspect\compose.yaml restart
   ```

`install.sh` 会先核对两件事：包没坏；检视工具改过的那四个档，实验室电脑上的是打包时当作基础的那一版。对不上它会停下来，不会装坏。上一版留在 `/work/inspect-code.prev`。

**11-17 面板第三版（每晚纪录）这一次要多做一步**：新的 `compose.yaml` 给 ops 加了可写的磁碟区 `nknu-ops`（挂在 `/ops`）和 `--ops-db /ops/ops.db`，先把新的 compose.yaml 放进 `C:\nknu-transfer\inspect\`，再 `docker compose -f C:\nknu-transfer\inspect\compose.yaml up -d ops`（`restart` 不会挂上新的磁碟区；磁碟区第一次 up 时自己建）。装好后打开 http://127.0.0.1:18878/api/history：`enabled` 是 `true`、`file` 是 `/ops/ops.db`，约一分钟后 `recorder.wrote` 大于 0（第一次会把每晚进库上线以来跑完的每一晚补记进去）；`enabled` 是 `false` 时 `why` 说为什么，首页「每晚進出」也会写。

## 页面长什么样子是哪里定的

11-17 起三个面板（检视台、资料库、资料总览）读同一份样式 `src/nknu/ops/theme/theme.css` 和同一条顶栏 `bar.py`（页面清单 `panels.json`），面板自己的样式里不准再写颜色（`tests/ops/test_theme.py` 会拦）。颜色只做四件事：文件类型（公告深蓝、一般网页浅蓝、附件橙、行事历绿、校外连结灰）、多少和缺多少（紫色）、好坏（绿、橙、红，只用在带图示的小标记上）、按钮和选中（墨色）。字号只有 11／12／13／14／16／20px。资料库的插件按档案路径载入 `bar.py`（它的容器没有 `nknu` 程序包）。

名字和说明的规矩（11-15 用户：「很多名字看着不直觉 然后感觉是想缩短文字 但又想保留细节导致不上不下的」）：页面上只放一个直白的名字，细节放进鼠标停上去才出现的悬浮框，样子和资料总览的一样。两个面板跑同一段悬浮框程序：Datasette 的 `static/tip.js`，检视台的 `look.py` 的 `TIP_JS`（测试会核对两份一样）；元素上写 `data-tip`（说明）和 `data-tip-h`（说明上面的名字），不用浏览器自带的 `title`。同一个意思在三个面板用同一个词（类型、主料／背景、合并、出处……），栏位的短名就是查询结果的栏名。

Datasette 的三样东西各在哪：表格页上面那排栏位和默认显示哪几栏是 `plugins/columns.py`（要改默认栏位就改它的 `DEFAULT`）；找网站的清单是 `templates/_sitefind.html` 加 `static/sitefind.js`；简体繁体都认是 `plugins/script.py`（字表 `plugins/t2s.json`，不用维护）。

| 面板 | 样子写在哪 |
|---|---|
| 检视台 | `src/nknu/ops/look.py`（颜色、样式、小脚本、图示）、`search_page.py`（搜索测试、成绩板）、`trace_page.py`（文件追踪）；成绩板的计算在 `board.py` |
| Datasette | `deploy/lab-inspect/datasette/templates/`（每一种页面，照 Datasette 0.65.5 的原版改写成中文）、`static/tc.css`（样式）、`plugins/guide.py`（表的中文名、栏位短名、地图）、`plugins/cells.py`（格子里的小标签和链接）；每个栏位的意思只写在 `metadata.yaml`，写法是「短名：说明」 |

Datasette 的模板是照 0.65.5 改的：换 Datasette 版本以前，要先拿新版的原版模板对一次。

## 三个服务各是什么

| 服务 | 实验室电脑的口 | 是什么 |
|---|---|---|
| `datasette` | 8001 | 现成的工具 Datasette（官方映像，0.65.5）。把资料库变成可以点、筛、数的网页。读正式库 `aca.db` 和教务处对照库 `aca1115.db` |
| `mcp` | 8766 | 我们的 MCP 服务，HTTP 模式。和以后给学生的 AI 用的是同一支程序、同一个库 |
| `ops` | 8878 | 检视台：搜索测试、文件追踪、网页核查三页（网页核查另外只读挂着爬虫的账本和 WARC） |

三个都不回答别的网站借你的浏览器、用它自己的名字连进来的请求。Datasette 和检视台只认本机名字（127.0.0.1、localhost）；MCP 服务另外也认它自己那台机器的位址。谁连得到它们，靠的是 Docker 只把口开在实验室电脑自己的 127.0.0.1 上。
